## 3. Constraints Audit

### 3.1. Primary Key and Unique Constraints
- **Primary Keys:** Every single table defines a single-column 64-bit `BIGSERIAL` (or `UUID` for `experiment_runs`) primary key named `<table_name>_pkey`.
- **Unique Constraints (12 explicit constraints):**
  1. `users(email)`
  2. `candidates(email)`
  3. `skills(name)`
  4. `dataset_versions(version_tag)`
  5. `blind_screening_results(resume_id)` (enforces strict 1-to-1 relationship)
  6. `experiment_metrics(experiment_run_id)` (enforces strict 1-to-1 summary)
  7. `job_skills(job_id, skill_id)` (`uq_job_skills_job_skill`)
  8. `resume_skills(resume_id, skill_id)` (`uq_resume_skills_resume_skill`)

## 5. JPA ↔ Database Validation (`ddl-auto=validate`)

The application was booted and validated directly against PostgreSQL 16.13 with `spring.jpa.hibernate.ddl-auto=validate`.

Hibernate's `GroupedSchemaValidatorImpl` verified every entity against the live catalog:
1. **Entities Validated (19/19):** `User`, `Job`, `JobRequirement`, `Candidate`, `Resume`, `Skill`, `JobSkill`, `ResumeSkill`, `BlindScreeningResult`, `BiasReport`, `RewriteSuggestion`, `MatchResult`, `AuditLog`, `DatasetVersion`, `DatasetRecord`, `Annotation`, `ExperimentRun`, `ExperimentResult`, `ExperimentMetric`.
2. **Enum Types:** All string-based enums correctly map to `VARCHAR` columns with matching lengths and `CHECK` clauses.
3. **UUID Types:** `ExperimentRun.id` and foreign key references in `ExperimentResult` and `ExperimentMetric` map cleanly to PostgreSQL native `uuid` columns.
4. **JSONB Types:** Mapped with `@JdbcTypeCode(SqlTypes.JSON)` for `redactions_log`, `missing_skills`, `demographic_ground_truth`, `exclusionary_phrases_labeled`, `hyperparameters`, and `details`.
5. **Array Types:** Mapped with `@JdbcTypeCode(SqlTypes.ARRAY)` for `skills.synonyms`, `dataset_records.jd_required_skills`, and `dataset_records.candidate_skills` to native `TEXT[]`.
6. **Timestamp Types:** Mapped with `java.time.Instant` to PostgreSQL native `TIMESTAMPTZ`.
7. **Generated Column:** `ExperimentResult.rank_change` mapped with `@Column(insertable = false, updatable = false)` to prevent write collisions with the PostgreSQL stored generated column.
8. **Nullability Checks:** All non-null database columns have matching `@Column(nullable = false)` declarations.

## 6. Demographic Data Isolation Audit

A full codebase scan was executed to verify demographic isolation:

```bash
grep -rn 'demographic' backend/src/
grep -rnE 'ethnicity|race' backend/src/
```

### Audit Findings:
- **Zero Exposure in Operational Entities:** No field named `demographic`, `ethnicity`, `race`, or `protected_attribute` exists on `Candidate`, `User`, `Resume`, `MatchResult`, or any operational DTO.
- **Strict Confinement to Research Domain:** The attribute `demographic_ground_truth` exists exclusively on `DatasetRecord.java` (`dataset_records` table).
- **Linguistic Scrutiny on BiasReport:** The only occurrence of `gender` in the Application Domain is within `BiasReport.java` (`gender_bias_score`, `gender_lean`), which evaluates the **linguistic phrasing of job descriptions** (e.g., masculine vs. feminine coded adjectives), NOT candidate demographics.
- **Zero Inferred Attributes Policy:** Verified that no heuristic, regex, NLP model, or fallback attempts to infer candidate demographic traits.

## 7. Audit Log Privacy & Retention Governance

Section 3.13 of [`docs/architecture/database.md`](file:///c:/Users/harhm/Downloads/FairHire_AI_Application/fairhire_ai/docs/architecture/database.md) and Section 3 of [`docs/architecture/domain-model.md`](file:///c:/Users/harhm/Downloads/FairHire_AI_Application/fairhire_ai/docs/architecture/domain-model.md) were inspected and verified for explicit privacy controls:

1. **Purpose of Storing IP Addresses:** Clarified that `audit_logs.ip_address` is retained strictly for access auditing, detecting unauthorized candidate unmasking during blind review, and platform security forensics.
2. **Exclusion from Research Datasets:** Explicitly stipulated that IP addresses and user audit records are strictly operational metadata and must never be merged into research corpora or benchmark metrics.
3. **Research Export Sanitization Policy:** Mandatory programmatic exclusion of `audit_logs` and all associated PII from any research reproducibility packages or dataset exports.
4. **Retention Policy:** Operational audit logs are subject to a 90–180 day rolling retention period, with read access strictly restricted to the `ADMIN` role.
